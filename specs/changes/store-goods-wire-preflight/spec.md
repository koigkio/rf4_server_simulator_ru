# 商店扣款前校验物品可下发性

Status: done

## Problem Statement

购买海钓吸引成分等商品时，玩家可能看到余额减少却看不到物品。物品已入库但无法生成客户端详情时，购买响应无法展示产出。

## Solution

合法的无钩吸引成分继续正常购买和展示；无法生成客户端物品数据的商品在扣款前拒购，保留玩家余额和库存。

## User Stories

1. 玩家购买无钩吸引成分后，可以在购买响应和重新登录后的背包详情中看到物品。
2. 商品定义异常导致无法下发时，购买失败且余额、库存和购买流水均不改变。

## Implementation Decisions

- 在 internal/gameserver 的 hStoreBuy 中，写事务前对全部预构造产出执行 ItemToTree 与编码校验。
- 保留现有无钩拟饵空 args(60) 投影，不改变响应类、字段或 args code；客户端基线为 4.0.25034。
- 保持已有事务、回执、退货和堆叠行为；不得在写事务内调用普通 DB 查询。
- 无表结构或迁移变更；旧物品仍通过现有详情投影读取。回滚仅需还原代码。

## Testing Decisions

- 使用真实临时 SQLite 和现有 handler 接缝，构造错误类型的出厂钩配置，分别验证银币和金币拒购后余额、物品和流水不变。
- 先在未修复实现上运行新增测试，预期拒购断言失败；加入预校验后通过。
- 使用独立协议表副本构造投影成功但编码失败的情况，分别覆盖银币和金币拒购。
- 保留并运行无钩吸引成分购买、重开数据库后的详情测试及商店堆叠、退货测试。
- 执行 go test ./...、go vet ./...、go build ./... 和 go run ./tools/doccheck；未完成的验证明确记录。

## Out of Scope

- 不变更协议契约、静态商品定义、幂等架构或玩家存档。
- 不自动退款、补发物品；本地部署脚本、配置及运行数据不纳入本次变更。
- 事务提交后的临时数据库故障及网络投递失败不属于此次预校验保证范围。

## Further Notes

[事实] 购买入库事务提交后才生成物品树，构造失败的物品被跳过。当前已有无钩吸引成分投影修复和购买可见性测试；本次补齐购买前的校验边界。
