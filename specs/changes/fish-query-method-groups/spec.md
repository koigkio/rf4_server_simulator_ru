# 查鱼按钓法分组推荐

Status: done

## Problem Statement

玩家查询鱼种时，回复只展示全局理论条/小时最高的前三条方案。某一钓法（常见是手杆或底钓）数值更高时，路亚候选会被全局截断挤出，玩家误以为该鱼只有一种高权重饵，无法按手头钓法选饵。

## Solution

查鱼回复按路亚、手杆、底钓三组分别列出高权重鱼饵。每组最多三条，组内按理论条/小时降序，并保留各自的最佳区域或落点；无可行方案的组不显示，存在缺组时在末尾说明只列出当前条件下的可行钓法。

## User Stories

1. 作为玩家，我希望看到同一鱼种在路亚、手杆、底钓下各自的高权重饵，以便按手头钓法选饵。
2. 边界：某组没有候选时不显示该组；有组缺失时明确提示“仅列出当前条件下有可行方案的钓法”。同一饵在不同钓法下出现时允许重复，因为钓组和区域不同。

## Implementation Decisions

- `internal/gameserver` 的 `QueryFish` 在按理论条/小时排序后，先按钓法族分组，每组最多三条，再做总上限截断；不再先全局取十二条再交给回复过滤。
- 分组：路亚族（含海图收索 50-54，海图 52 海钓鱼肉归路亚）、浮钓族（手杆）、沉底族（底钓）；未知钓组归“其他”。
- `formatFishQueryReply` 按固定组顺序渲染，组内编号从 1 开始；`EquivalentBaits > 1` 时在饵名后显示“同效饵 N 个”。
- 计算链路、协议、表结构、经济与结算不变；查询仍只读，不掷鱼、不扣饵、不写玩家数据。
- 帮助文本与 `docs/gameplay.md` 同步“按路亚、手杆、底钓分组、每组最多三条”的口径。

## Testing Decisions

- 单元：`TestFishQueryPlanFamilies` 验证 rig→族映射、每组最多三条、组内理论条/小时降序，以及同 `map/bait/rig` 只保留最高值。
- 回复：`TestFishQueryReplyCompactReference` 覆盖三组、同效饵和参考点只输出一次；`TestFishQueryReplyLimitedAndNoInventedCoordinate` 覆盖单组截断与缺组提示。
- 现有查鱼区域、只读、协议回环测试保持通过；回滚分组逻辑后上述分组断言会变红。
- 门禁：`go test ./...`、`go vet ./...`、`go build ./...`、`go run ./tools/doccheck`。自动测试不替代游戏内实机验收。

## Out of Scope

- 不扩展代表钓组（仍为内陆 1/12、海图 55/52/50/51），不扩大天然饵、拟饵各 24 组的候选上限，不保证全饵或全图最优。
- 不新增查询语法（如“河鲈 路亚”），不改客户端协议或消息形状。

## Further Notes

- [事实] 旧实现 `QueryFish` 全局取前十二条，`formatFishQueryReply` 再取前三条；内陆天然饵候选只配 1/12，拟饵只配 5。
- [事实] 默认配置下 `companion_bait_fish` 的等价饵合并会把同档位饵折叠为一个代表，`EquivalentBaits` 记录数量。
- 实机验收：在游戏内发送鱼名，确认三组标题、每组编号、区域或落点行，以及缺组提示。
