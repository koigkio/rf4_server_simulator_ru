# 管理界面功能对齐与工作区布局

Status: in-progress

## Problem Statement

本地服主在默认管理台无法按年份填入活动奖励，也看不到整条任务线的完成奖励。切换商店、玩家或页签时，地址、编辑对象和待保存内容不总是一致。接口未返回数据时，一些页面仍给出“离线”“全部关闭”“没有记录”等确定结论。笔记本上的导航和说明栏还会同时挤压中间表单。旧版页面能完成某项操作，不代表用户从默认入口也能完成。

## Solution

在默认管理台恢复仍受支持的操作，使用户能确认“正在改谁、哪些值会写入、是否已经生效”。登录、切页和短时失联不应无声丢弃草稿。控制中心区分进程日志与操作审计；玩家门户区分新购买与确认上一次购买。布局优先给当前任务留空间，辅助说明在空间不足时下移。

## User Stories

1. 作为服主，我能在“游戏参数 → 限时活动”选择一套或全部预设，只补已开启分支的空白阶段；能核对普通阶段与全部完成奖励，最后一次保存。
2. 作为管理员，我只改昵称就只提交昵称；切人、切店、重试或放弃操作，不会误改另一个对象，也不会把旧余额或旧草稿写回去。
3. 作为调参者，我能按数据来源核对鱼种、鱼饵、鱼钩和活动设置，分清游戏默认、已保存、未保存和暂时读不到的值。
4. 作为本地玩家，我能从故障入口直接看对应进程输出；会话过期可以重新登录，购买回执不明时可以确认原订单，不用再次扣款。
5. 作为笔记本、手机或纯键盘用户，我能到达所有页面、选中候选项、关闭弹窗并回到原控件；首屏优先展示当前任务而不是重复的导航和统计。

## Implementation Decisions

覆盖默认管理台 `internal/admin/web/app/` 的 12 个一级页面、共用组件、仍可访问的旧版后台、启动器 `cmd/launcher/` 及玩家门户 `internal/portal/`。下列编号是验收与拆分 PR 的索引，不是一项大改的提交清单。P1 优先防止误写、重复操作、草稿丢失及恢复关键功能；P2 恢复查询、说明和辅助操作。各项为拟实现要求，不表示已修复。

### 默认管理台

| 编号 | 页面与优先级 | 必须能完成的操作与边界 |
|---|---|---|
| E1 | 游戏参数：活动奖励，P1 | 在 `#tuning/event` 提供七、八、九周年及 2025、2026 新年共五套和“全部预设”。从现有资源填入**已启用分支的空白阶段**，保留手改草稿、已有阶段和未启用分支；任何资源失败均不部分填入。填入不保存、不发奖。可选普通阶段及阶段 `0`（整条任务线完成奖励，不是奖杯）；可预览保存内容、清空可选分支草稿、放弃或保存。保存及回读后保留当前分支/阶段。活动未开或无分支时不可写。 |
| E2 | 游戏参数：活动配置，P1 | 奖励数量、增删、分支和时间都纳入草稿保护。保存分支、切换活动或页签前不丢未保存奖励；放弃后复选框、日期、集合及预览一致。切换失败时按服务端实际模式回显，不保留失败选项的高亮。 |
| S1 | 商店与库存，P1 | 下拉选店、点击店铺、切价格/库存、书签和刷新均保留同一店与页签；无效店不回退到一个可写首店。恢复按商品名称搜索、按水域定位店铺和“只看改过的”；查询不能只覆盖首批返回的商品。含基础金币价为零的商品也可编辑金币覆盖，银/金/件单位各自正确。 |
| S2 | 商店保存，P1 | 区分留空继承、显式零和取消整件覆盖。若接口只支持整件恢复，确认框应说明会同时恢复哪些价格和库存；一行恢复不清掉其他行草稿。保存后回读生效价、库存与覆盖标记；多件部分成功时列明成功和待重试项。 |
| P1 | 玩家管理：档案与选人，P1 | 更新只发送改动字段；只改昵称不得附带打开时的等级、经验、货币或会员。快速从甲切乙，慢响应、延迟刷新与危险操作均不得指回甲。恢复在线列表刷新，不覆盖在编字段；无状态显示“未上报”，已到期会员不显示为有效会员。 |
| P2 | 玩家管理：背包、鱼护、记录、技能、邮箱，P1 | 同名装备显示槽位或短实例号并带入删除确认。鱼护补录支持场景、钓点和显式鱼种选择，搜索文本不能充当 ID。图鉴显示实钓档位；重量仅在主动留空时自动，非法文本不转零。技能点校验范围、回显服务端值。邮箱显示可区分的邮件号及附件摘要，支持核对后重发；写操作不以列表位置识别对象。 |
| M1 | 邮件与旧版发信，P1 | 支持由玩家档案进入、按已知 UID 核对或显式选择搜索结果；不得默取同名首项或沿用上个玩家。无权限提示登录并保留目标、正文和附件，不循环重载；查询失败不显示成零匹配。选择器、侧栏、预览和确认框的 UID 一致。数量输入无效时不发送；模板覆盖已有正文前可取消。一次确认只提交一次；只返回排队回执就显示“已入队”，不承诺已送达。 |
| R1 | 钓场与鱼口，P1 | 切换二级页签或模式前保护草稿，重复点当前页签不重置。预设只说明实际覆盖的五项，欢乐时光独立。三种发鱼模式保留；比例可拖动也可精确键入，支持整组恢复出厂，拒绝全零；放弃后滑杆、数值、比例图一致。多项写入若不能整体保存，须标出已生效项并只重试剩余项。 |
| W1 | 水域与鱼种，P1 | 区分读取失败、空名册和确实不出鱼；未成功读取或显式水域失效时不得在其他水域写入。批量按钮显示实际范围和匹配数，零匹配禁用。“停用”与“移除覆盖”分开：移除后重读结果应符合文案，若不支持删除就不提供假删除。展示权重来源（周档/人工/静态）、轮换组、模式及下次切换时间。 |
| W2 | 鱼群区域，P2 | 保留内陆绘制、名单、独占/增益、保存删除。恢复挪威海只读浏览、平移、缩放及可取得的定位，不重新开放海上建区。旧版窄屏地图与属性栏不互相裁掉；地图核心操作提供可聚焦的工具或等价输入。 |
| H1 | 钩子手感，P2 | 尺寸选项独立于第一批或当前过滤结果，返回后显示值与查询一致。单型号的四项参数可核对，包括折叠项；恢复默认先回填，再统一保存，或在立即写入前确认。非法值或请求失败后可在原弹窗更正重试。搏鱼参数链接应到“游戏参数 → 玩法与钓组 → 鱼”，不另造搏鱼页。 |
| B1 | 鱼饵偏好，P2；草稿保护为 P1 | 恢复按 Tier 3 筛鱼、逐饵证据和占比、首选/保底/不吃判定与跨饵料/拟饵搜索。列表按鱼搜索和选饵器搜饵须准确标明；关闭已改抽屉前可选继续编辑。键盘可选单饵或整类；开关指引直达“玩法开关 → 鱼会挑饵”。保留允许、拒绝、底钓与宽松/严格轮换。 |
| D1 | 总览，P2 | 发鱼方式与鱼汛风格分别取对应状态；恢复总览自动刷新和全服邮件数。失败项显示未取得并可重试，不推定开、关、零或无修改；仅报告已知的数据来源。刷新不打断搜索或输入。 |
| D2 | 发布说明、关于、更新和路由，P2 | 发布文件缺失、网络错误和空文档分开，失败可重试。README 目录在本页定位，不新开后台或回退总览。可用镜像、官方、预览及说明链接全部可到达；当前版本取实际来源，跳过只影响该版本且所有横幅同步。保留旧商店、钓场、参数及发布说明书签映射；失效对象提示重新选择。 |
| A1 | 审计日志，P2 | 用明确的动作分类区分玩家补录与全局技能设置；显示可核对的动作码，计数与列表使用同一分类。从玩家页进入带目标 UID，标明只筛最近 200 条；无记录、无匹配和读取失败分别显示。 |

### 共用组件、控制中心与玩家门户

| 编号 | 范围 | 行为要求 |
|---|---|---|
| C1 | 登录、表单与交互，P1 | 异步失败或本地校验失败都恢复提交按钮；登录长时间未响应时防重复提交。登录成功原路由、草稿和选择保持。确认弹窗有可读名称，限制焦点在弹窗内，关闭后归还焦点；仅最上层响应 Esc，有草稿时先确认。错误对读屏可感知。主题选择支持方向键、确认、Esc，显示已保存主题；候选项和旧版登录标签可用键盘及读屏操作。 |
| L1 | 导航与工作区，P1 | 优先保证表单和表格宽度。桌面导航建议 216–224 CSS px，保留图标、标题、当前项，编号和副标题不常驻；约 40px 行高，不靠缩小文字塞满。中栏使用剩余宽度，辅助栏按**工作区可用宽度**决定并排、折叠或下移。手机用紧凑页名和菜单，保留全部入口。只读文档不显示“保存后生效”；水域和单型号页不声称影响全部水域；未知指标不补零。 |
| X1 | 启动器与托盘，P1 | 一次状态轮询失败只提示断连，不卸载后台 iframe 或丢草稿。后台等待/初始化失败时能重试和返回首页；端口冲突、无法打开浏览器时给出可操作的地址或日志位置。停止、重启及托盘退出明确是否停服和断开玩家，保留只启动客户端的独立入口。 |
| X2 | 启动器状态与日志，P2 | 故障入口直接定位进程输出（非后台审计）。组件表显示进程构建版本、来源及磁盘程序已替换提醒；未就绪不显示“运行中/已加载”或内部状态码。轮询保留按钮焦点；阅读旧日志时不强制滚底，复制区分筛选结果和全部，失败可知。窄屏表格在组件内部滚动或堆叠，操作列可达。 |
| U1 | 玩家门户，P1 | 会话过期或退出返回 401 时清掉本地过期身份，可重新进入；重选当前导航不意外退出，键盘可操作进入/退出。对结果未知的本地金币购买，优先用原请求号确认或重试，不因扣款后余额不足禁用确认入口，不生成第二次新购。不得把旧余额标为实时余额。 |

### 拆分、接口与兼容

- 先交付 E1（含默认入口回归），再按独立问题处理 E2、玩家/商店写入目标、C1、U1、X1；L1 可独立交付。其余项目不与布局或奖励预设绑定。按[贡献指南](../../../CONTRIBUTING.md)一项明确问题一个 PR，尽量一个 commit，最多三个相关 commit；每个行为改动随附能单独失败的测试。
- 在现有管理 API、原生页面组件和已嵌入资源上实现。优先复用已有读写接口；如需增加只读详情，单独评审字段可见性。匿名只读权限不扩展到玩家详情或写操作，保留审计。登录、收件人核对或购买重试不得绕过服务端校验。
- 不改表或迁移，不改变 `event_stage_gifts` 格式、旧存档、游戏协议及客户端基线 `4.0.25034`。阶段 `0` 即使未编辑也须原样保存。功能回滚以独立 PR 为单位，不删除已存奖励或重放购买；旧页保留为兼容入口，不作为默认页验收的替代品。

## Testing Decisions

以下均为实现 PR 的验收条件。浏览器加载发布使用的真实 HTML、ES 模块和样式；数据用隔离夹具。控件要通过正常用户入口操作，同时断言画面、目标与请求，不仅检查源码含有某个词。

| 覆盖 | 可使回归变红的场景与预期 |
|---|---|
| E1、E2 | 默认入口开启九周年分支 19、20，各有阶段 0–7。在分支 19 的 0、1 预置自定义奖励，其一为未保存草稿。填入九周年恰补 **14** 个空阶段，重复填入补 **0** 个，两个原值不变，填入期间 **0** 次写请求。覆盖五套及全部、停用分支、请求失败、只清已启用分支、手动保存后回读阶段 0、放弃及切页。预期来自固定夹具及现有预设资源，不由被测合并函数生成。 |
| S1、S2、P1、P2 | 使用两家店和两个合成玩家；由店乙点击库存后保存，只允许写店乙。零基础金币价可设置金币；清一行不丢另一行。延迟玩家甲的详情至乙之后返回，仍显示和操作乙。打开档案后模拟余额增加，仅改昵称，断言请求无资产字段、存储余额保留新值。用同名实例、过期会员、非法重量和非数字技能点覆盖各子页。涉及持久写的断言使用临时 SQLite。 |
| C1、M1、U1 | 登录返回 401 后原地重试成功，正文、附件和 UID 不变；Tab/方向键/Enter/Esc 可完成选择与取消。重复昵称必须选定目标，双击只提交一次；排队非送达。门户模拟购买已入账、响应中断、余额不足，再确认原请求：仅一笔扣款一份回执。退出时 401 后能重新登录。 |
| R1、W1、W2、H1、B1 | 分别覆盖：全零权重不能保存、出厂值与放弃不同、切标签可保稿；水域读取失败不可写、过期链接不选首项、批量只改匹配行、移除后重读；海图只读而内陆可编辑；钩号筛选跨查询保持且保存失败可重试；饵料证据可筛、关闭可取消、可仅用键盘选饵。 |
| D1、D2、A1、X1、X2 | 独立注入无数据、403、404、500、短时断连及恢复。总览自动更新但不伪造零值，文档锚点不改业务路由，四类可用更新链接都可点。核对玩家 UID 与审计分类。打开带草稿 iframe 后令一次轮询失败，恢复后草稿仍在；诊断入口显示指定进程输出，复制筛选日志不含被过滤行。 |
| L1 | 在 320/390、1024、1259/1260、1280、1366、1440、1920 CSS px 宽度检查。建议验收值：1280×800 时 12 个一级入口无需滚动，活动编辑区至少 640px 且比任一辅助栏宽；1259→1260 时不因插入说明栏而减半；320×800 时页名和首个任务控件同屏。默认页与启动器嵌入态均无整页横向溢出；宽表允许局部滚动。以元素几何与键盘可达性断言，不以整页截图一致代替。 |

运行默认后台、门户及对应旧版兼容用例（`node --test internal/admin/*_ui_test.cjs internal/portal/ui_test.cjs`）；旧版用例和默认页用例分开报告。文档门禁 `go run ./tools/doccheck`；实现 PR 提交前运行 `go test ./...`、`go vet ./...`、`go build ./...`。报告实际结果与未验证项；不将浏览器夹具当作真实游戏客户端发奖或原生托盘实测。

## Out of Scope

不新增活动年份或猜测缺失奖励，不改变发奖、奖杯、经济或幂等机制。不恢复明确停用的海上建区、背包直发物品；不新建独立搏鱼页，不重建已经迁到首页的诊断页。不把所有 CSS 像素机械替换为百分比，不更换技术栈、引入第三方素材或修改外部游戏客户端。本规格不涉及真实支付、账号运营或远程管理平台。

## Further Notes

首批实施范围：默认入口已恢复活动预设与阶段 0（E1/E2），调整导航和工作区（L1），修正商店选店、查询与覆盖保存（S1/S2）、玩法参数与水域写入（R1/W1/H1），并改善玩家档案、邮件、鱼饵与登录流程。控制中心的 iframe、日志和玩家门户原单重试已有独立夹具。完整验收仍包括旧版邮件、只读海图（W2）、原生托盘与启动错误提示、总览/文档/审计以及真实服务联调，不能以本批 UI 用例替代。

- [事实] 预设和阶段 0 的语义见[历年活动奖励预设](../historical-event-reward-presets/spec.md)、[活动阶段奖励](../event-stage-gifts/spec.md)与[旧版编辑器](../../../internal/admin/web/legacy.html)。默认入口使用[游戏参数模块](../../../internal/admin/web/app/pages/tuning.js)；[已有奖励浏览器测试](../../../internal/admin/event_stage_gifts_ui_test.cjs)加载旧页，故须单测默认入口。
- [事实] [管理台外观规格](../admin-console-restyle/spec.md)将诊断信息并入首页，并要求未登录的编辑者登录后不丢输入。[布局样式](../../../internal/admin/web/app/theme-aerial.css)同时使用固定下限、比例和断点；L1 的尺寸是拟验收目标，不是现有效果或通用设计标准。
- [推断] 全字段保存及同页异步响应可能使表单对过期数据或错误对象写入；以 P1 的交错响应与存储夹具验证，不假定发生过真实玩家资产损失。管理端边界以[管理端与热更参数契约](../../capabilities/admin-and-tunables.md)为准。
- [事实] 第二轮评审修复：浮层保存条只归当前页面所有，旧页迟到的保存结果不再点亮或提交；活动奖励保存前先回读，已生效项按成功处理，只重写仍等于原基线的项；邮件发送遇到 401 时原地登录并保留草稿，由管理员确认后重发；「刷新本页」先确认主页面和侧页的未保存修改；控制中心每个组件只保留一个在途日志请求。见 [会话与路由用例](../../../internal/admin/session_route_ui_test.cjs)。
